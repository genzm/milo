# 図の接続・配置の修正

`dist/ddd解像度を上げる_Milo20枚_図解の重複解消版.md` と生成HTMLで再現した不具合を、Markdown側の座標調整ではなくMiloの描画処理で修正する。

## 原因と実装方針

| 箇所 | 原因 | 修正 |
| --- | --- | --- |
| 5枚目の原因分解 | 分岐の幹線が子ノードの範囲だけを結び、親がその範囲外にあると途切れる | 分岐・合流の幹線に親・合流先の接続座標も含める。上下左右の4方向に適用 |
| カードと矢印の位置 | `scrollHeight` が枠線を含まず、整数に丸められる。HTMLの実寸とSVGの配置用寸法が異なる | 変形前のCSS寸法と枠線込みの内容寸法を測り、確定したフレームをHTMLとSVGで共有する。表示倍率や小数幅にも対応 |
| 14枚目の放射状図 | 上下左右の辺の中央を接続点にするため、斜めの関係が不自然な線になる | 中心同士を結ぶ直線と、丸いカードの実際の輪郭との交点を使う |
| 項目数の多い放射状図 | 中心との距離だけを確認し、枠外のカードを個別に押し戻していた | 全カードの組合せで離隔を確保。横長の余白を使って配置し、必要なら全体を同率で縮小。読めない縮尺は既存の警告で通知 |
| 16枚目の因果網 | 合流する矢印の終点が同じ。曲線の接線方向も接続面と一致しない場合がある | 同じ面の接続点を相手の位置順に分配し、曲線を接続面に垂直に出入りさせる |
| 曲線ラベル | 曲線を描く前の直線・折れ線からラベル位置を計算していた | 描画する曲線の長さに沿った中央付近に配置 |
| 矢印の先端 | SVGマーカーの基準点が先端より内側にあり、カード内部へ入り込む | マーカーの先端をパス終点に揃える |
| 分岐の中央線の高さ | 各列の外接矩形を独立に中央寄せしており、カードの高さが異なると中央の枝が親とずれる | 隣接する階層の中央の接続先を揃え、列内の順序・カード間隔を制約として詰め直す。奇数は中央の枝、偶数は中央2本の中点を基準にする。左右・上下の流れと合流にも適用 |
| 同じ段の線の微小な傾き | 上端が同じでも高さ100と108のカードでは中心が4ずれる | 接続面の中央領域が重なり、面を共有する他の線がない場合は共通の高さ・横位置で直線にする |
| 黒いボックス直前の曲がり方 | 曲線の終点での接線だけが水平で、矢印の直後では急角度になる | 有限長の水平・垂直接近区間を確保。幅に対して上下移動が大きい狭い隙間では、丸い角と直線の中間区間を使う |

元のMarkdown本文・ノード指定は変更せず、同じ入力を再コンパイルする。明示した固定サイズに内容が収まらない場合は、枠を黙って拡張して線をずらすのではなく、内容超過を通知する。

中央線の整列は `route=auto` の自動配置に適用する。手動固定・オフセットのある配置は保持する。整列によってカードが重なったり列の順序が逆転したりする制約は採用しない。高さ自動の横向き図は必要な領域を確保し、固定領域では収まる場合に整列する。

## 検証

- 単体テスト：非対称な分岐・合流を4方向で検証。丸いカードとの接続、密な放射配置、自由配置の合流・接線・ラベルを検証。
- `test/fixtures/diagram-regressions.md`：元資料から環状図、原因分解、比較座標、放射状図、因果網の5枚を保存。
- Chromium：印刷用描画、編集画面の2種類の幅、発表表示で、カードの重なり、内容の切れ、矢印の接続、無関係なノードへの線の侵入、フッターへのはみ出しを検査。
- 元資料のHTMLを再生成し、図のある5枚をスクリーンショットで確認。

```sh
npm run check
npm run build
npm test
node cli/milo.mjs 'dist/ddd解像度を上げる_Milo20枚_図解の重複解消版.md'
```

任意の固定座標・任意の項目数で常に読めることを保証するものではない。指定された図の領域が小さすぎる場合や、自由配置でノード自体を重ねた場合は、入力側の領域・配置の調整が必要になる。
