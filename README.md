# milo 0.1

原稿・モデル・画像・編集道具を持つ、自己編集可能な単一HTMLです。
このリポジトリから各自で `milo.html` を生成します。生成後の使用には外部CDNやサーバーへの接続は不要です。

## 使い方

Node.js (v22以降)をインストールして以下を実行します。

```sh
npm ci
npm run build
```


生成された`dist/milo.html`をデスクトップ版ChromeまたはEdgeで開きます。
右上の「自動保存を接続」を押し、いま開いたHTMLを選んで書き込みを許可します。

右側の原稿とモデルを編集します。入力が落ち着いてから約500msで同じファイルへ保存します。入力を続けている間も、おおむね2秒ごとに保存を試みます。
閉じる前に「保存済み」を確認してください。ブラウザや設定によって、再度ファイル選択や許可が必要な場合があります。

`Cmd+S` / `Ctrl+S` はブラウザの「ページを保存」ではなく、miloの即時保存として動きます。未接続なら保存先の接続を開始します。


## 開発する場合



サンプルは3枚です。2枚目で係数とグラフ、3枚目で埋め込まれたGIFを試せます。
右上の「発表する」、または入力欄以外で F キーを押すと発表モードになります。左右キーでページを送り、Escで編集に戻ります。

### 保存されるもの

- 編集モードでの原稿・係数・式・画像・レイアウトの変更。
- 発表モードでスライダーを動かした係数の変更。

発表中に動かしたスライダーの値も、通常の係数変更として自動保存されます。カーソルや生成されたDOMは保存しません。

ブラウザ内の退避とファイルハンドルの記憶は、IndexedDBが使用可能なときの補助機能です。
文書の正本はHTMLファイルです。未接続時の編集を、ファイルに保存済みとは表示しません。

## 原稿と数式

```markdown
# 減衰振動

現在の減衰率は {{wave.gamma}} です。

通常の文章の一部は `++下線++` のように囲むと下線を付けられます。

::equation{model="wave"}
::text{
ここに **複数行の補足説明** を入れます。

- 箇条書きなどのMarkdownも使えます。
}
::plot{model="wave" from="0" to="10"}
::slider{param="wave.gamma" label="減衰率" min="0" max="1" step="0.01"}

::image{asset="asset-loop" alt="GIF"}

説明用の式: $E=mc^2$

::footer
出典や補足など、スライド下部に小さく表示する文章。
```

モデルはJSONCです。変数を一箇所で定義し、式の構文木から数値計算と表示用TeXを生成します。

```jsonc
{
  "input": "t",
  "parameters": {
    "gamma": 0.2,
    "omega": 3.0
  },
  "expression": "exp(-gamma * t) * cos(omega * t)"
}
```

式の文法: 数値、変数、括弧、`+ - * / ^`、`sin cos tan exp log sqrt abs min max pow`、定数 `pi e`。
`^` は右結合で、`-2^2` は `-(2^2)` です。任意のJavaScriptや任意のTeXを数値評価する機能はありません。
自由な説明用TeXはKaTeXの対応範囲で組版します。

## ファイル形式とGit

HTMLは、上部の `MILO TOOLBOX` と、本文側の `MILO DOCUMENT` に分かれます。
前者には固定のスタイル・依存コード・実行コードをまとめ、後者には固定IDの非実行スクリプト区画を置きます。
文書区画は設定、スライド、モデル、素材の順にまとまり、新しいソースも対応する区画へ追加されます。無効化中の部品用区画は、将来戻せるよう空のまま残しています。
発表順は `SLIDES` 区画に並ぶスライドブロックの物理順です。追加・移動・削除ではブロック自体を並べ替えるため、HTMLを読む順番と発表順が一致します。

```html
<script type="application/x-milo-source"
        id="model-wave" data-kind="model"
        data-name="wave.jsonc" data-codec="amp-lt-v1">
{ "parameters": { "gamma": 0.2 } }
</script>
```

データ区画は `amp-lt-v1` でエンコードします。`&` → `&amp;`、`<` → `&lt;`、NUL → `&#0;` です。一度だけデコードします。
これにより原稿・コード中のHTML終端タグやコメントが、外側のHTMLを壊しません。

保存先に接続すると、選んだファイルの元の文字列を読み込みます。ブラウザで表示されているDOMを保存に使いません。
元の文字列とソース位置を保持し、対象範囲だけを置き換えます。未変更部分の空白、コメント、改行、BOM、依存コードを維持します。
UTF-8が対象です。

係数を変更した場合の差分:

```diff
-    "gamma": 0.2,
+    "gamma": 0.3,
```

「変更を見る」は、この画面で開いた時点とのソース比較です。Gitのコミットとの差分ではありません。
コミット・ブランチ・過去版への復元は、通常のGitで管理します。

## 保存の限界

- ファイル選択と書き込み許可はブラウザが管理します。許可なしで、自分の保存元パスにアクセスすることはできません。
- 同じパスのHTMLを更新しますが、APIは通常、一時ファイルを作ってclose時に置き換えます。物理的に変更バイトだけをディスクへ書く実装ではありません。
- 同一タブ内の書き込みを直列化し、保存前・書き込み直前・保存後に内容を確認します。外部変更を検知すると停止します。
- File System Access APIにはGitなど別プロセスと協調するOS全体のcompare-and-swapがありません。確認と置換の間の競合を完全には防げません。外部でHTMLを書き換える際は、保存を確認してエディタを閉じてください。
- 任意のHTMLを読み込む汎用エディタではありません。この文書形式を対象にします。
- GIFなどのバイナリ素材はBase64として埋め込むため、素材そのものを差し替えた差分は人間向けの内容比較にはなりません。
- SVG画像の外部参照・スクリプトは取り込みません。ラスター画像を含め、画像は12MBまでです。
- カーネルは固定です。文書中から編集するのは原稿・モデル・素材です。カーネルを変更する場合は、この開発用ソースから再ビルドします。

## 開発する場合

Node.js (v22以降)をインストールして以下を実行します。

```sh
npm ci
npm run check
npm run build
npm test
```

すると`dist/milo.html`ができます。
`content/slides.md` が初期スライド原稿です。

行全体が `---` の箇所で区切り、上から順にスライドとして扱います。区切りを増減すればスライド数も増減します。
`content/seed.mjs` が各位置のID・レイアウトとモデル・素材、`src/` がカーネルです。ビルド時にMarkdownとランタイム、KaTeXのWOFF2フォントを埋め込み、外部依存のないHTMLを生成します。
通常の文書編集ではビルドは不要です。ビルドはseedから初期文書を生成するため、編集中のHTMLに対して実行する操作ではありません。
生成後にHTML内で行った編集は `content/slides.md` へ逆同期されません。再ビルドすると、初期スライドは `content/slides.md` の内容から作り直されます。
依存関係はpackage-lock.jsonで固定しています。依存ライブラリのライセンスは、ビルド時にリポジトリの `THIRD_PARTY_NOTICES.txt` へ生成します。生成HTMLには格納しません。

## 検証範囲

型検査と自動テストを含みます。ソースの保持、最小差分、特殊文字、式の評価、保存中の追加入力、外部変更、書き込み失敗、保存後の再起動を検証します。
画面の結合テストはHappy DOM、保存先は模擬ファイルハンドルを使用します。
これは実際のChromiumの描画・権限ダイアログ・ネイティブファイルへの書き込みを検証したものではありません。この作成環境ではローカルHTMLの実ブラウザ検証が制限されています。

実機で確認する際は、コピーしたサンプルHTMLで「接続 → 係数変更 → 保存済み → 閉じて再度開く」を最初に試してください。
